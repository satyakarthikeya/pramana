# Platform audit, 25 October 2026

Branch `fix/saikrishna/platform-audit`. Method: a clean install on Windows (Python 3.12,
`pip install -r requirements.txt`, which pulled pandas 3.1, numpy 2.5, langfuse 5.0,
langgraph 1.2, scikit-learn 1.9), the app started with the offline profile, and a scripted
end-to-end run (sign up, upload, Report, Measured, Analyse, results, export, Ask, Memory)
on a 600-row daily table. The code was then read module by module. Two read-only
reviews covered the verification gateway and the analysis tiers; every finding below was
reproduced or confirmed in the code before it was fixed.

## 1. Why "nothing works"

| # | Symptom | Root cause | Status |
|---|---|---|---|
| 1 | The first analysis seems to hang for about 10 minutes at "Writing verified memory" | The 79 MB memory embedding model downloads lazily inside the first run that has a PASS (measured: 562 s of a 569 s run) | **Fixed**: the model is loaded in a background thread at server start (`ChromaLessonStore.warm`). The same run now takes 10 s |
| 2 | Ask (chat) never answers without a DeepSeek key and Langfuse | Chat had no non-model path | **Fixed**: a rule-based assistant (`chat/rules.py`) speaks the model's protocol, so the number guard, the gateway and the ledger all apply unchanged. It is selected by configuration (`PRAMANA_CHAT_ENGINE`; default `rules` in the offline profile), never as a fallback after a model failure |
| 3 | "Start analysis" uploads, then the run fails | With a model engine configured and keys missing, the server accepted runs that could only fail | **Fixed**: the run is refused up front (503 with the missing names); the Home screen warns before upload |
| 4 | Ordinary daily tables get almost every claim "not testable" | `period_keys` rolls a daily axis longer than 183 days up to months, so one reading per day looked like "several rows per month" and the table became `transactions`, with the first categorical column as its "entity" | **Fixed for the gate**: `data_structure_for` gives the gate a daily time series when each day has one row. The Exact tier keeps its monthly view (deliberate, tested) |
| 5 | CSV numbers stored as text, and "1,200" stays text | pandas 3 reads text as the `str` dtype; `is_object_dtype` is False for it, so text-to-number conversion never ran | **Fixed** in `cleaning.py` and `reader.py`; thousands separators handled when every value uses them |
| 6 | Semicolon, tab and latin-1 CSV exports fail or load as one column | Ingestion hard-coded UTF-8 and the comma | **Fixed**: delimiter sniffing, then the UTF-8 (BOM-aware) and cp1252 encodings in turn; the row limit is applied while reading |
| 7 | One network blip during a run shows "This run could not be loaded" until a reload | `useRun` stopped polling on the first error | **Fixed**: polling retries with backoff and the message appears only if the problem persists |

## 2. Correctness and safety fixes in the gateway (stricter only)

| Severity | Finding | Fix |
|---|---|---|
| critical | `evaluate_gate` accepted a NaN q-value and returned SUPPORTED (`nan >= alpha` is False; `min(1, nan)` is 1) | Refuses a q that is not a finite probability |
| critical | `_p_value` gave a NaN statistic the smallest possible p (every comparison with NaN is False), and NaNs in the null lowered p | Raises on a non-finite observed value or null, so the claim fails closed |
| major | One claim's crash in `execute()` or in proof building aborted the whole batch: no proof for any claim | Contained per claim: that claim is rejected with the reason, the others are unaffected |
| major | A direction asserted on a more-than-two-group claim (unsigned metric) was silently ignored, so "A is higher" could pass with A lowest | Refused with a reason |
| major | A reference group not found among the labels ("1" vs "1.0", case) fell back to alphabetical order, judging the opposite sentence | Labels are matched after normalisation; otherwise the claim is refused, never re-oriented |
| minor | Sandbox stderr decoded with the Windows locale codec (garbled reasons) | UTF-8 on both sides |

## 3. Other fixes

- **Privacy:** verified memory was shared between accounts. Another user's lessons (with
  their column names and findings) appeared on the Memory page, in search and as run hints.
  Browse, search and hints are now scoped to the signed-in account's own runs.
- **Datasets can be deleted** (`DELETE /api/datasets/{id}` and a button): file, runs and chat
  go; verified memory is kept.
- **Dependency bounds:** upper bounds on pandas, numpy, langfuse, langgraph and chromadb at
  the verified majors. `langfuse>=2.40` was too loose: the code needs v3+
  (`start_as_current_observation`).
- **UI:** the chat's testing ledger was crushed into a sliver below about 1240 px (it now
  stacks); rule-based answers no longer show invented token counts.

## 5. Needs the verification owner (AGENTS.md §8.10): flagged, not changed

1. **Trend power on time series.** On the daily table a clear upward trend (0.3 per day,
   noise SD 20) is INCONCLUSIVE. The differenced null tests the mean of the differences,
   which has very little power against a linear trend with this noise.
2. **Block sign-flip p-floor.** The null is discrete: 20 periods give p ≥ 0.0147, so with
   four trend claims in a family q cannot reach 0.05. `significance_leg` assumes 1/(B+1).
   The forecast p-floor is 2/(B+1).
3. **Attacks that crash leave a PASS standing** with no attacks run (documented as "a crash is
   not evidence"). PERIOD_CHANGE and SEASONALITY get no attacks at all.
4. **Group differences in time-series and panel tables** are NOT_TESTABLE (no whole-series
   null yet). This is honest, but the reason text reads like a missing feature.
5. `effect_metric` is not covered by the HMAC stamp, and nothing checks it against the claim
   type. A model-written program could pick a metric with a weaker floor. This matters only
   with `generator=llm`.
6. Trend claims on more than 3,000 rows: the Sen slope is computed after the test and raises,
   so the claim ends INCONCLUSIVE at p = 1.
7. Admissibility matches causal and universal words in column names (a column called `make`
   or `all` blocks every claim about it).
