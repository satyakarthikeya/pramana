## Correction to earlier notes

Project memory previously flagged an open decision between "claim-type dispatch" and
"dtype dispatch" for the stats layer. **The repo has already resolved this**:
`falsification/templates.py` dispatches on `ClaimType` (correlation / group_difference /
trend) with hand-written deterministic code per type — not a dtype-keyed generic
`pramana.stats.test()`. The LLM (DeepSeek V4) generator is a second, optional code path
behind the same interface, gated by config, and is explicitly allowed to not exist yet
(`test_selecting_the_unbuilt_llm_generator_raises`). Build against the deterministic
path first; the LLM path is genuinely last, not a blocker.

## What running the suite locally will show right now

Every stub file listed above will raise `ImportError`/`AttributeError` the moment a
test tries to import a real class or function from it (e.g. `CandidateInsight`,
`apply_bh`, `permutation_test`). This was not run in this session (this scan happened
from a Linux sandbox without the project's Windows virtualenv) — run it yourself:

```
cd pramana
.venv\Scripts\activate
pytest tests/unit/contracts tests/unit/verification -q
```

Expect a wall of collection/import errors for everything in the stub list, and green
(or close to green) for nothing yet, since even `contracts` — the step-1 dependency of
literally everything else — is unimplemented.
