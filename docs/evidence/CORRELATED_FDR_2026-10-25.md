# Does Benjamini-Hochberg still control false discoveries when claims share columns?

Status: DESIGN WRITTEN BEFORE THE FIRST RUN (committed first; results are appended below the
line "RESULTS" afterwards and nothing above that line is edited after seeing numbers).
Date: 2026-10-25. Branch `feat/satya/eval-correlated-fdr`. This is experiment E2 of
`docs/RESEARCH_improvements.md` and the W3 hole named in `docs/RESEARCH_verification_agent.md` A6.
It changes no source, config or test; it only measures. Any number quoted from it needs the
verification owner's sign-off (AGENTS.md 8.10).

## Question

When the claims of one run share columns (so their p-values are dependent), does the repo's
`apply_bh` (one correction per run, `q < alpha` strict, as in `bh_rejections`) keep the
false discovery rate at or below alpha = 0.05 (value read from `configs/verification.yaml`)?

## Simulation design

* Run size m in {8, 24, 40} claims, each a Spearman-type association claim between two columns.
* True-effect fraction in {0 (all null), 0.25, 0.5}. The truth of a claim is defined by the
  population covariance used to generate the table: a pair is "true" iff its population
  correlation is non-zero, and every other claimed pair has population correlation EXACTLY zero
  (checked by an assertion in the script). A design where a null predictor is secretly correlated
  with a true one through a third column would make "false discovery" ambiguous, so the
  generator never builds one.
* Row count n = 150, Gaussian columns (ranked before testing, so the statistic is Spearman).
* Three claim structures, all built from a pool of shared columns:
  1. star: one outcome y against m predictors. The true predictors form one equicorrelated
     block T and the null predictors another block N, each with within-block correlation rho in
     {0, 0.3, 0.6, 0.9}; T and N are independent of each other. Each true predictor has marginal
     correlation beta with y.
  2. chain: columns c0..cm, claims (c_i, c_{i+1}). A true edge has correlation beta, a null edge
     exactly zero (columns generated by a Markov recursion). Neighbouring claims share a column.
     rho does not apply.
  3. block: a bipartite design, outcomes x predictors, with the predictors in blocks of size b
     (b = 2, 3, 5 for m = 8, 24, 40; 2, 4, 4 outcomes) with within-block correlation rho in
     {0, 0.3, 0.6, 0.9}. Truth is assigned per (outcome, block) cell, so a whole block is true or
     null for a given outcome; the number of true cells is round(fraction x cells) and the
     realised true fraction is reported (it equals the target in every cell of this grid).
* Effect strength: beta = 0.35, shrunk where needed so the covariance matrix stays positive
  definite (this happens when many correlated true predictors share one outcome). The realised
  beta is reported. Because the shrink lowers power in the biggest star cells, power is a
  by-product and is reported but is NOT the claim of this study.
* p-values: the repo's own `pramana.verification.stats.permutation_test`, two-sided, one test per
  claim with its own seed, 1000 permutations (REDUCED from the configured 10000, for runtime; the
  p-value floor is 1/1001, which is far below alpha/m at m = 40, so BH is not floor-limited at
  alpha 0.05 with these sizes. The mild extra discreteness makes the p-values slightly conservative
  not anti-conservative). The statistic is a plain dot product of standardised ranks, which is
  Spearman's rho up to a constant; it is used instead of `spearman_rho` only because the latter is
  about 50 times slower per permutation. The shuffle, the add-one p-value and the seed handling are
  the library's.
* Corrections applied to the SAME p-values in each replicate: BH (`apply_bh`, reject `q < alpha`),
  Holm step-down (family-wise), and BY (BH at alpha / H_m, H_m the harmonic number, i.e. BH q
  multiplied by H_m).
* Replicates: at least 500 per cell where affordable (target 1000), master seed 20261025, each
  (cell, replicate) seeded by a `SeedSequence` child, so the output is reproducible and
  independent of the number of worker processes.

## Metrics (fixed now)

Per replicate and method: V = false rejections, R = rejections, FDP = V / max(R, 1), an
any-false indicator (V >= 1), and true-discovery proportion (rejected true / true).
Per cell and method: FDR = mean FDP with Monte-Carlo SE = sd(FDP)/sqrt(reps) and a 95% normal
interval; FWER = P(V >= 1) with SE sqrt(p(1-p)/reps) and a Wilson 95% interval; power.
In the all-null cells FDP = 1[V >= 1] exactly, so FDR and FWER are the same number for BH
(a check the script asserts).

Judging rule: a cell EXCEEDS alpha if the lower end of its 95% interval for FDR is above 0.05.
A cell is "within noise" if the interval straddles 0.05. Cells with the point estimate above 0.05
are listed either way. BH theory gives FDR = alpha * (m0/m), so at 25% and 50% true the expected
FDR is about 0.0375 and 0.025 if BH is exact for these p-values (it is conservative, not exact,
for discrete p-values and for dependence).

## Bad result and what it would mean (fixed now)

* Bad: any cell where the FDR lower 95% bound is above 0.05, most likely at high rho, m = 40 and
  a small true fraction (m0/m large). Report where and by how much. Do not change alpha, the
  design or the replicate count to make it pass.
* Also bad, and reported as such: the all-null FWER of BH above 0.05 plus two standard errors.
* Not bad: FDR well under 0.05 (that is what m0/m < 1 predicts). BY and Holm will be far more
  conservative; their lower power is expected, not a finding.
* If a bad cell appears, the decision belongs to the repo owner (verification owner,
  AGENTS.md 8.10): switch the in-run correction to BY (guaranteed under any dependence, costs a
  factor of H_m, about 2.7 at m = 8 and 4.3 at m = 40) or to a joint permutation max-T
  (Westfall-Young; needs one joint resampling of all claims, which the repo cannot do today
  because claims use different null schemes). No code is changed here.

## Limits stated in advance

Gaussian continuous columns and one permutation scheme only (free shuffle); the real gateway
also uses stratified, cluster and block-differenced nulls and a confirmation split, none of which
is simulated. Sizes are small (m <= 40, n = 150). All dependence is positive: every within-block correlation and every planted effect is positive. Negative or mixed-sign dependence, the setting the research note asked about, is NOT simulated here and remains unmeasured. Two-sided Spearman-type claims only.
