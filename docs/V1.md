## 1. The product in one paragraph

A person uploads a table of data. PRAMANA proposes claims about it, **runs real statistical
tests on each claim**, corrects for testing many claims at once, and shows only the findings
that survive, each with its proof. Everything rejected is shown separately as *not a finding*,
with the reason. Verified findings are remembered, and past lessons are offered as hints on
later datasets (never as evidence). No claim is ever shown as a finding without passing
the gate: `memory_write ⟹ verdict == PASS` (AGENTS.md §0).

## 2. The V1 user journey (this is the acceptance script)

1. Open `http://localhost:8080`.
2. Upload a CSV or XLSX; optionally type a question.
3. Watch the run move through stages until it finishes.
4. Read **Verified findings** (PASS): plain-language claim, effect size and strength, q-value,
   sample size, and a way to open the proof.
5. Read **Rejected claims** (REJECT): the claim, the plain reason (not significant after
   correction, effect too small, wrong direction, could not be tested, could not be run).
6. Open **Verified memory**: lessons from PASS findings only; search them.
7. Upload a second dataset and see a relevant past lesson offered as a hint.
8. Download the results.

If a stranger can do steps 1 to 8 without help and without a terminal beyond the start command,
V1 is done.

## 3. In and out of V1

**In:** upload; cleaning and profiling; schema inference (rules); claim proposal by the rule
scan, optionally by hosted Gemma; the full verification gateway; proof objects; PASS-only
memory; the dashboard; export; one-command start; README.

**Out (do not build, do not mention as features):** Langfuse tracing, Celery, Redis, Docker
and cloud deployment, the A/B/C/D evaluation and benchmark runs, Gemma refinement and
cleaning suggestions, episode selection, categorical-versus-categorical claims (Cramér's V),
bootstrap intervals, multi-user accounts, more than one run at a time.

## 8. Limitations to state at the review

* The gateway cannot reject a well-powered association that is really a confound; there is no
  held-out split or adjustment.
* The effect floors do not separate truth from chance; the corrected q-value does. Small real
  effects PASS (29 demo PASSes with current floors; a stricter tier would give 23).
* Two-category claims (for example area by education) are not testable.
* No confidence intervals on effect sizes.
* The trend test refuses datasets above its row ceiling.
* One run at a time.
* The LLM generator path has one small live run (9 claims); its refusal rate at scale is unmeasured.
