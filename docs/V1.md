## What V1 is

One local flow, no extra services:

```
upload CSV/XLSX -> clean + profile -> propose claims -> verification gateway
   -> insights with proof objects -> PASS-only memory -> dashboard shows results
```

Everything runs in one process behind the API. **Out of V1 on purpose:** Langfuse tracing,
Celery/Redis/Docker, cloud deployment, the A/B/C/D evaluation, Gemma refinement and
cleaning suggestions, episode selection in the UI, Cramér's V, bootstrap intervals.

## How to run (once item 2 is settled)

```
.venv\Scripts\activate
pip install -r requirements.txt
$env:PRAMANA_API_VERIFICATION_MODE = "inprocess"
$env:PRAMANA_VERIFICATION_GENERATOR = "template"     # or set DEEPSEEK_API_KEY and use llm
uvicorn pramana.api.main:app --port 8080
# open http://localhost:8080 and upload a CSV
```

## Known limitations to state at the review

* The gateway cannot reject a well-powered association that is a confound; there is no
  held-out split or adjustment.
* Floors do not separate truth from chance; `q < alpha` does. Small real effects PASS
  (29 demo PASSes with the current floors; a stricter tier would give 23).
* Categorical-versus-categorical claims are not testable (Cramér's V out of scope).
* No confidence intervals on effect sizes (bootstrap deferred).
* `sens_slope` refuses datasets above its row ceiling (quadratic memory).
* One run at a time (`max_active_runs: 1`).
* The DeepSeek path has one small live run (9 claims); its refusal rate at scale is unmeasured.
* Template and LLM paths agree on that run; no systematic comparison yet.
